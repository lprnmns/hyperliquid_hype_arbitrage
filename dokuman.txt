1. Executive Summary and Goals
Overview
This bot exploits basis (spread) discrepancies between Hyperliquid's HYPE perpetual futures (perp) and spot HYPE/USDC markets. Strategy: When basis exceeds a threshold (e.g., 25-35 bps), open short perp (leveraged 2-3x) and long spot positions via IOC orders for speed. Close via ALO (post-only) for fee savings when basis nears zero, with IOC fallback after 30 minutes.
Goals:

Achieve passive income with small balances (100-300 USDC) via frequent micro-arbs.
Minimize latency (<50ms RTT from Mumbai VPS to Hyperliquid nodes on Arbitrum).
Optimize fees: Target net edge >10 bps per trade after costs.
Vault-free operation: Use master account address + agent private key for signing.
Rust-native for performance: No GC pauses, async I/O with Tokio, multi-threaded on 2 cores.

Expected Performance (Simulated):

Trades/day: 5-20 (depending on volatility).
Annualized ROI: 10-30% (conservative, assuming 15 bps net edge, 10 trades/week).
Risks: Funding rate flips, slippage, liquidations (mitigated via low leverage).

Tech Stack Highlights:

Language: Rust (with Tokio, tungstenite, ethers).
No DB in hot path: In-memory state with optional Redis for logs.
Deployment: Dockerized on VPS, 24/7 with systemd.

3. Strategy Deep Dive: Logic, Flows, and Triggers
3.1 Basis Calculation
Basis (bps) = 10_000 * ((perp_mid - spot_mid) / spot_mid).
For short perp/long spot: Use perp_bid / spot_ask for entry edge.
Advanced: Impact-adjusted = Cumulative price for target size from L2 book.
3.2 Entry Flow

Monitor WS feeds (BBO/L2).
Compute bps every tick.
If bps >= entry_threshold:
Calc size: notional = (leverage / (leverage + 1)) * available_balance.
Qty = round(notional / price, sz_decimals).
Send batch IOC: Perp short (limit_px ~ perp_ask), Spot long (limit_px ~ spot_bid + slip).

Handle partial fills: Retry remainder with IOC.

ASCII Flow:
textWS Tick → Compute BPS → Threshold Check?
                  ↓ No → Loop
                  ↓ Yes
Calc Size → Build Payload → Sign → WS Post
                  ↓
Fill Update → Partial? → Hedge Remainder
3.3 Exit Flow

If bps <= exit_threshold:
Send batch ALO reduceOnly: Perp long, Spot short (post-only prices).

Timer: After 30min, if not filled: Cancel → IOC fallback.
Funding Check: If positive funding, delay exit up to 1hr.

3.4 Triggers and Edge Cases

Volatility Filter: Skip if IV > 100% (query from /info).
Position Limits: Max 1 open arb at a time.
Re-entry: If basis re-widens while open, ignore (delta-neutral focus).

3.5 Simulation Example
Assume entry at 30 bps, size 200 USDC, leverage 3x:

Perp short 450 contracts @ 1.003 USDC.
Spot long 150 HYPE @ 1.000 USDC.
Exit at 0 bps: Profit ~6 USDC minus fees.


4. Order Types, TIF, and Execution Rules
From Hyperliquid Docs (2025):

IOC (ImmediateOrCancel): Fills immediately or cancels unfilled. Use for entry.
ALO (AddLiquidityOnly/PostOnly): Rejects if it would take liquidity. Use for exit (maker fees).
ReduceOnly: True for closes; prevents increasing position.
Cloid (ClientOrderId): 16-char string for tracking (e.g., "arb-uuid-perp").
Batch: Up to 10 actions in one payload.

Rules:

Limit orders only (no pure market; set limit_px aggressive for IOC).
Rounding: Price to tick_size, Qty to sz_decimals (floor for buys, ceil for sells?).
Min Notional: Reject if <10 USDC.


5. Fees, Net Edge Calculation, and Optimization Strategies
5.1 Fee Schedule (From /info, 2025)

Perp Maker: -0.015% (rebate).
Perp Taker: 0.025%.
Spot Maker: 0.02%.
Spot Taker: 0.04%.
Total Entry (IOC taker): ~0.065%.
Total Exit (ALO maker): ~0.005%.
Grand Total: ~0.07% (7 bps).

5.2 Net Edge Formula
net_bps = entry_bps - (entry_fees + exit_fees) - slippage_est + funding_est.
Example: 30 bps entry - 7 bps fees - 2 bps slippage + 1 bps funding = 22 bps net.
5.3 Optimization Ideas

Hybrid Entry: 20% ALO probe + 80% IOC.
Funding Arb Layer: Hold if funding >0.01%/hr.
Slicing: Split large orders into 5-10 chunks.
Rebate Hunting: Adjust ALO prices for max rebate.
Tier Upgrades: Track volume for lower fees.
Slippage Minimizer: Use L2 depth to cap size.

7.2 Price Impact Calc
rustfn impact_price(book: &L2Book, side: Side, target_qty: f64) -> f64 {
    let mut cum_qty = 0.0;
    let mut weighted_px = 0.0;
    for level in book.levels(side) {
        let fill = (target_qty - cum_qty).min(level.qty);
        weighted_px += fill * level.px;
        cum_qty += fill;
        if cum_qty >= target_qty { break; }
    }
    weighted_px / target_qty
}

rustuse std::sync::{Arc, Mutex};
use tokio::sync::mpsc;
use tokio_tungstenite::{connect_async, tungstenite::Message};
use url::Url;
use ethers::signers::{LocalWallet, Signer};
use ethers::types::transaction::eip712::{Eip712, TypedData};
use serde::{Deserialize, Serialize};
use anyhow::Result;
use chrono::Utc;

#[derive(Debug, Serialize, Deserialize, Eip712)]
#[eip712(name = "Hyperliquid", version = "1", chain_id = 42161, verifying_contract = "0x032b6bd9684b0554775c6600269af126fd3d7a4f")]
struct OrderAction {
    action: serde_json::Value,  // JSON of orders
    nonce: u64,
    vault_address: Option<String>,
}

#[tokio::main]
async fn main() -> Result<()> {
    let config = Config::load();  // From YAML
    let state = Arc::new(Mutex::new(AppState::new()));

    let (tx, mut rx) = mpsc::channel(32);  // For decisions to sender

    // WS Manager Task (Core 1)
    let ws_handle = tokio::spawn(ws_manager(tx.clone(), config.ws_url.clone()));

    // Decision & Sender Task (Core 2)
    let decision_handle = tokio::spawn(decision_engine(rx, state, config));

    tokio::join!(ws_handle, decision_handle);
    Ok(())
}

async fn ws_manager(tx: mpsc::Sender<Message>, url_str: String) -> Result<()> {
    let url = Url::parse(&url_str)?;
    let (ws_stream, _) = connect_async(url).await?;
    let (mut write, mut read) = ws_stream.split();

    // Subscribe
    let sub = serde_json::json!({"method": "subscribe", "subscription": [{"type": "l2Book", "coin": "HYPE"}]});
    write.send(Message::Text(sub.to_string())).await?;

    while let Some(msg) = read.next().await {
        let msg = msg?;
        if let Message::Text(text) = msg {
            tx.send(Message::Text(text)).await?;  // Forward to decision
        }
    }
    Ok(())
}

async fn decision_engine(mut rx: mpsc::Receiver<Message>, state: Arc<Mutex<AppState>>, config: Config) -> Result<()> {
    while let Some(msg) = rx.recv().await {
        if let Message::Text(text) = msg {
            // Parse L2, compute bps

            if bps >= config.entry_bps {
                let payload = build_order_payload(/*...*/);
                let sig = sign_action(&config.agent_privkey, &payload, &config.master_address).await?;
                // Send via WS or HTTP
            }
        }
    }
    Ok(())
}

// Signing function
async fn sign_action(privkey: &str, action_json: &str, master: &str) -> Result<String> {
    let wallet: LocalWallet = privkey.parse()?;
    let nonce = Utc::now().timestamp_millis() as u64;
    let msg = OrderAction {
        action: serde_json::from_str(action_json)?,
        nonce,
        vault_address: None,
    };
    let typed_data = msg.encode_eip712()?;
    let sig = wallet.sign_hash(typed_data)?;
    Ok(hex::encode(sig.to_vec()))
}

// Rounding helpers
fn round_price(px: f64, tick: f64) -> f64 {
    (px / tick).round() * tick
}

fn round_qty(qty: f64, decimals: u32) -> f64 {
    let factor = 10f64.powi(decimals as i32);
    (qty * factor).floor() / factor
}
